## A. 凭证与权限（找内部同事 / 企业管理员）

| # | 需要确认/调研 | 为什么重要 | 结论 |
|---|---|---|---|
| A1 | WPS 开放平台（open.wps.cn）是否已有可用的**企业应用**？没有的话如何创建（需要企业管理员？需要付费版本？） | 没有应用就拿不到凭证，一切无法开始 | |
| A2 | 应用的 `client_id`（APP_ID）和 `client_secret`（APP_KEY）——由谁保管，是否能写入我们项目的 `.env` | 对接层必需；敏感信息保管方式影响部署 | |
| A3 | 应用类型：**自建应用**（走 client_credentials 租户 token）还是其他？我们当前代码按"自建应用 + 租户级 token"编写 | 类型决定 token 获取方式，选错会认证失败 | |
| A4 | 应用需要申请的 **API 权限 scope** 清单（多维表格读写，疑似 `kso.dbsheet.read` / `kso.dbsheet.write` / `kso.dbsheet.readwrite`） | 权限不足时接口返回 403，需提前申请 | |
| A5 | **表格授权方式**：把应用加入目标多维表格的协作者？还是该表格必须在应用所属租户内？个人版表格能否被 API 访问 | 决定我们能用哪个表格 | |
| A6 | 目标表格的 **`file_id`**（表格 URL 中的 ID）和 **`sheet_id`**（工作表 ID），从哪能看到 | 对接层必需参数 | |
| A7 | token 有效期与刷新机制：租户 token 约 2 小时，是否有其他限制（并发、频率） | 影响缓存与调用频率设计 | |

## B. 表格结构（与建表同事确认）

| # | 需要确认/调研 | 为什么重要 | 结论 |
|---|---|---|---|
| B1 | 目标表格是否按方案建好列：**日期 \| 简报内容 \| 附件 \| 源状态 \| 统计 \| 运行ID \| 采集时间**（见 `config/settings.py` 的 `BITABLE.field_map`） | 列名不一致会写入失败（`prefer_id=false` 按列名写） | |
| B2 | 各字段**类型**：日期=日期/文本？简报内容=文本？附件=「图片和附件」？运行ID/统计/源状态=文本？ | 类型不匹配（如日期列写了字符串）可能写入失败 | |
| B3 | 「日期」列能否作为**筛选条件**用于 upsert 查询（filter operator 对文本/日期字段是否支持 `is`） | upsert 依赖"按日期查已有记录"，若 filter 不支持要改查询方案 | |
| B4 | 附件列「图片和附件」是否允许**一次挂多个文件**（多选），以及**单文件大小上限** | 附件方案 A 的前提 | |
| B5 | 是否提供**测试表格**先联调（避免直接污染生产表） | 联调期建议先跑测试表 | |
