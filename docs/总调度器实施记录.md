## 1. 模块 A：批次注入机制（_latest 覆盖写）

### 1.1 目标

让调度器能以"固定批次目录"驱动各采集器：同一天多次运行写入同一 `{source}_{YYYYMMDD}_latest` 目录，覆盖写不堆积（方案书 3.3）。

### 1.2 修改内容

**核心约束**（方案书 3.3.3 已核实）：collectors 下 17 个 crawler 模块全部在 `fetch()` 内覆盖 `self._batch_dir`（代码形态一致），仅改 `base.py` 不会生效，必须逐模块加条件保护。

| 改动点 | 内容 |
|---|---|
| `collectors/base.py` `__init__` | 新增 `self._batch_dir: Optional[str] = os.getenv("BATCH_DIR")`，从环境变量读取注入的批次目录（未注入时为 `None`） |
| 17 个 crawler 模块 `fetch()` | 批次目录赋值改为条件保护：`if not self._batch_dir: self._batch_dir = ...`，注入时不覆盖 |

条件保护完全向后兼容：不注入 `BATCH_DIR` 时行为与现状一致（独立运行采集器不受影响）；注入时采用调度器指定目录。

**hkex 特殊处理**：`fetch()` 主流程中 L458 附近的批次目录赋值需加条件保护，且保护后 PDF 下载目录须从注入目录推导（`os.path.join(self._batch_dir, "pdfs")`），保证 PDF 仍落盘在注入批次内。

#### 3.2.3 真实采集暴露的系统性 bug 修复（17 个 crawler + 解码回退）

**Bug 表现**：真实采集 cninfo 首次运行崩溃 `ValueError: I/O operation on closed file`。

**根因**：所有 crawler 头部用 `sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding='utf-8')` 替换 stdout/stderr 对象。替换后原对象失去引用被 GC，GC 时关闭共享底层 buffer，导致后续 `print` 抛异常。该模式在独立运行时偶发不触发，但 subprocess 环境下高频复现。

**修复方式**：改用 `reconfigure()` 直接改编码，不替换对象：

```python
import sys
# 强制 UTF-8 输出：用 reconfigure 改编码，不替换 sys.stdout/stderr 对象
# （替换后原对象被 GC 会关闭共享 buffer，导致 print 抛 "I/O operation on closed file"）
sys.stdout.reconfigure(encoding='utf-8')
sys.stderr.reconfigure(encoding='utf-8')
```

- 覆盖全部 17 个 crawler 模块（cninfo 首跑即修，其余 16 个一次批量修复；kingsoft_ir / kingsoft_office_ir 仅有 stdout 单行；kingsoft_office_ir 另删除多余 `import io`）
- 编译通过、lint 0 错误、`TextIOWrapper` 残留 0 处

**连带改进**：`orchestrator._decode_output` 原仅按 UTF-8 解码（`errors="replace"`），Windows 下采集器 GBK 输出会乱码。改为"先 UTF-8，失败回退 GBK"：

```python
def _decode_output(raw: Optional[bytes]) -> str:
    if not raw:
        return ""
    try:
        return raw.decode("utf-8")
    except UnicodeDecodeError:
        return raw.decode("gbk", errors="replace")
```

# 模块 D：汇总与主产物

## 概述
在模块 A（批次注入）、模块 B（scheduler 基础包）、模块 C（采集编排）基础上，
实现方案书 3.4/3.5/3.6 的汇总层：只扫各源 `_latest` 批次加载 → 24h 时间过滤 →
L1/L2 去重 → 排序 → 附件归集 → 产出主产物 `output/latest.json`。

## 修改内容

| 文件 | 改动 |
|---|---|
| `scheduler/summarizer.py`（新增） | 汇总主流程：`find_latest_batch_json` / `load_latest_batches` 只扫各源最新 `_latest` 批次；24h 过滤；去重；排序；`collect_attachments` 附件归集；`run_summary` 产出 `latest.json`（schema_version=1，含 sources 状态 + stats + items） |
| `pipeline/__init__.py` | **L2 去重增强**（方案书 3.5）：`_normalize_title` 增加繁简转换（opencc，不可用时降级）+ 剥离通用前后缀（`快讯:` / `独家\|` / `【快讯】` / `\| 来源：xxx`）；归一化后为空标题退化为 URL 分组，避免多条误归并 |
| `scheduler/orchestrator.py` | 采集后接入汇总；落地 CLI 语义：`--skip-collect` 只汇总（各源标记 pending）、`--dry-run` 只采集不汇总 |
| `config/settings.py` | `TIME_FILTER.default_hours` 48→24（方案书 5.2 决策点 #2，汇总层统一 24h 兜底）；新增 `LATEST_JSON`、`LATEST_ATTACHMENTS_DIR` 并纳入目录创建 |
| `requirements.txt`（新增） | 记录项目第三方依赖 + `opencc-python-reimplemented`（L2 繁简转换所需） |
| `scripts/check_summarizer.py`（新增） | 模块 D 验证脚本 |

### 关键设计点
- **汇总只扫 `_latest`**：历史时间戳批次不参与汇总，避免重复归集。
- **采集器超采由汇总层兜底**：采集器按自身时间窗抓取，汇总层统一按 `TIME_FILTER.default_hours=24` 过滤（方案书 3.4.1）。
- **L1 URL 去重 + L2 标题归一化去重**：跨源同事件按可信度优先级保留（官方公告优先）；`_normalize_title` 繁简转换 + 去通用前后缀。
- **附件归集**：`output/latest_attachments/` 扁平拷贝 PDF，并更新 item 的 `pdf_path` 指向归集后路径。
