# 虎嗅采集器接入失败原因分析

> 记录日期：2026-08-05
> 结论：虎嗅网被阿里云 Web 应用防火墙（WAF）全链路拦截，当前环境下无法通过常规方式（HTTP 请求 / Playwright 浏览器自动化）采集标题与正文。虎嗅采集器暂不启用。

---

## 1. 问题背景

本项目目标是自动化采集金山系（金山办公、金山软件、金山云、西山居）相关资讯。虎嗅（huxiu.com）为计划接入的科技媒体之一（`collectors/huxiu/crawler.py`，参考第一财经采集器模式实现）。

从 2026-08-05 的采集日志（`output/logs/collectors/huxiu/2026/08/05.log`）可以看到，当天的多次尝试全部返回 0 条结果，且日志中反复出现"检测到验证码保护"：

```
11:38  [金山软件] 成功提取 0 条       —— 页面为验证码页，无搜索结果
11:58  [金山软件] 虎嗅网触发了验证码保护，无法继续采集
14:09  [金山软件] 虎嗅网触发了验证码保护，无法继续采集
15:01  [金山软件] 检测到验证码保护 → 等待10秒后重试 × 3 → 重试次数用尽，跳过
15:24  [金山软件] 已启用 playwright-stealth 反检测模式 → 仍然触发验证码
```

> ⚠️ 特别注意：日志 15:20 处还暴露出一个与本问题无关的代码 Bug —— `stealth(page)` 以"module 对象不可调用"报错（`playwright_stealth` 导入路径为 `from playwright_stealth.stealth import Stealth`，实例应通过 `Stealth().apply_stealth_sync(page)` 调用）。此问题在已选方案下不再需要修复，但若日后恢复虎嗅采集需一并处理。

## 2. 现场排查结论

### 2.1 阿里云 WAF 挑战页

对虎嗅发起任意请求（首页、搜索页、文章详情页、栏目页、移动端），服务器返回的不是正常页面，而是**阿里云 WAF 的挑战（验证）页面**。特征如下：

- HTML 头部包含 `aliyun_waf_aa` / `aliyun_waf_bb` 两个 meta 标签，用于 WAF 风控校验；
- `<title>` 为空（无内容）；
- 页面约 15,885 字节，不含任何业务数据（无 `window.__INITIAL_STATE__`）；
- 加载阿里云滑动验证码组件（`aliyunCaptcha`、`nc-container`、滑块）。在浏览器中渲染时标题为「滑动验证页面」。

```html
<!-- 被拦截时的响应头特征 -->
<meta name="aliyun_waf_aa" content="ff926c7f07e45e2e487a29a6197d3460">
<meta name="aliyun_waf_bb" content="eade71455e2ad9c6d08b82bc7d98df8c">
```

### 2.2 各种接入方式的实测结果（2026-08-05）

| 接入方式 | 结果 |
|----------|------|
| 普通 HTTP 请求（requests/httpx，正常 UA） | ❌ 返回 WAF 挑战页，无数据 |
| Playwright 无头浏览器 + 基础反检测脚本 | ❌ 渲染为「滑动验证页面」，无数据 |
| Playwright 无头 + playwright-stealth | ❌ 仍触发验证码 |
| Playwright 有头浏览器 | ❌ 返回 153 字节空壳页面 |
| 首页预热会话 → 搜索页 | ❌ 搜索页仍被拦截 |
| 搜索页直接 URL 访问（`/search?keyword=金山办公`） | ❌ 被拦截 |
| 文章详情页直接 URL（`/article/4880708.html`） | ❌ 被拦截 |
| 移动端 m.huxiu.com | ❌ 被拦截 |
| RSS / feed / 栏目页 | ❌ 被拦截 |
| 站点地图 sitemap.xml 及 site_map/article_*.xml | ✅ 可正常访问（见下） |

**关键结论**：拦截发生在 WAF 层，发生在任何页面业务逻辑之前。无论使用哪种客户端、加不加反检测脚本，只要是当前机器的出口 IP 发起请求，都会被判定为风险流量并拦截。因此**问题不在采集代码的提取逻辑，而在更上游的网络访问被阻断**。

---

## 3. 分析：为什么会被拦截

阿里云 WAF 的挑战机制（非本项目的代码问题，而是目标站点安全策略）通常基于以下维度综合判定：

1. **IP 信誉**：数据中心 IP / 已知代理 IP 段风险高。当前运行环境的出口 IP 很可能属于此类，被直接列入高风险。
2. **TLS/HTTP2 指纹（JA3/JA4）**：自动化 HTTP 客户端与真实浏览器的 TLS 指纹不同。
3. **浏览器自动化特征**：`navigator.webdriver`、Canvas/WebGL 指纹、行为模式等（已尝试隐藏，但无法对抗 IP 层面的拦截）。
4. **Cookie/会话历史**：全新会话无历史，与真实用户的长期会话差异明显。

> 需要说明：**规避阿里云 WAF 的验证码属于攻击性行为**，本项目不应采用绕过手段（如打码平台、指纹伪造、代理池对抗等）。以下记录均指合法的接入方案评估。

## 4. 曾经可行的备选路径及现状

### 4.1 站点地图 sitemap（唯一可正常访问的路径）

- `https://www.huxiu.com/sitemap.xml` 为 sitemap 索引，可正常访问（HTTP 200）；
- 其中包含 `site_map/article_1.xml` ~ `article_N.xml` 等文件，每个约 5000 个 URL，**含文章链接和最后修改日期**（`<lastmod>`，精确到天），可覆盖当天的文章。

```xml
<url>
    <loc>https://www.huxiu.com/article/4880708.html</loc>
    <lastmod>2026-08-05</lastmod>
</url>
```

- **局限**：sitemap 只提供 URL 和日期，**不含标题、正文**。而文章详情页本身被 WAF 拦截，无法进一步获取标题和内容。仅凭 URL 无法构建有意义的资讯条目（本项目 NewsItem 必须有 `title`）。

### 4.2 搜索引擎收录（可访问，但不可用于正文）

- 百度 / 必应 / 搜狗可通过 `site:huxiu.com` 检索到虎嗅文章（实测可访问），但结果页仅含标题摘要，无法替代虎嗅详情页，且不适用于系统化采集。

### 4.3 RSSHub 等第三方 RSS 服务

- 实测 rsshub.app 无法连通（连接超时）。即便连通，RSSHub 的虎嗅源同样需要绕过 WAF，不保证可用。

## 5. 已评估但不采用的做法（明确排除）

| 方案 | 不采用原因 |
|------|-----------|
| 打码平台 / 滑块自动拖动 | 属于绕过 WAF，合规与稳定性风险高，且虎嗅风控会持续升级 |
| 代理 IP 池对抗 | 成本高、易失效，且属规避行为 |
| 伪造浏览器指纹对抗 | 实测无效（拦截在 IP/TLS 层），且不可持续 |
| 使用真实用户 Cookie | 需人工登录并维护 Cookie 有效期，运维成本高；当前无可用 Cookie |

---

## 6. 建议与后续动作

1. **短期（当前决策）**：在 `config/settings.py` 中保持虎嗅采集器 `enabled: False`，不纳入每日采集流程。金山系资讯已由财联社、第一财经、36氪、证券时报等媒体源覆盖。
2. **中期（可选）**：
   - 关注虎嗅是否提供官方合作 API / RSS 订阅（需联系虎嗅媒体合作）；
   - 评估第三方转载源（如虎嗅公众号文章的转载渠道）。
3. **若日后 IP 环境变化**（例如在住宅 IP / 允许环境下运行），可重新评估，并先修复 `stealth` 调用 Bug，再小流量测试首页能否获取正常页面。
