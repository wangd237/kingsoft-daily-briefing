# 总调度器运行指南

本文档说明如何在本地（Windows / PowerShell）运行总调度器并查看效果。

## 1. 环境准备（首次）

```powershell
cd e:/gh-projects/Issue1

# 安装依赖
pip install -r requirements.txt

# Playwright 浏览器（stcn / huxiu / eastmoney 等源需要）
playwright install chromium

# （可选）配置 AI 摘要：复制 .env.example 为 .env 并填写
# AI_API_BASE / AI_API_KEY / AI_MODEL
# 未配置时采集器自动跳过摘要，不影响采集与汇总
```

## 2. 快速开始

```powershell
# 1) 查看启用源清单（不实际运行）
python -m scheduler.main --list-sources

# 2) 跑一次完整链路（采集 → 汇总 → 简报 → 运行报告）
python -m scheduler.main

# 3) 只想跑单个源（最快验证）
python -m scheduler.main --sources cninfo
```

运行结束控制台会依次打印：每源采集状态 → 汇总统计 → 简报路径 → 运行报告路径。

## 3. CLI 参数

```powershell
python -m scheduler.main --help
```

| 参数 | 作用 | 适用场景 |
|---|---|---|
| `--sources cninfo,stcn` | 只跑指定源（逗号分隔） | 单源调试 |
| `--max-workers 4` | 并发采集数（默认 4） | 网络不稳时降到 2 |
| `--dry-run` | 只采集不汇总 | 只看采集原始结果 |
| `--skip-collect` | 只汇总不采集（重跑汇总/调去重） | 已有数据时复用 |
| `--no-briefing` | 跳过简报生成（MD+HTML均不生成） | 只想看 latest.json |
| `--list-sources` | 打印启用源清单后退出 | 检查源配置 |
| `-v` | 打开 DEBUG 日志 | 排查问题 |

注意：`--dry-run` 与 `--skip-collect` 互斥，不能同时指定。

**单独生成简报（不采集、不汇总）**：
```powershell
# 默认双产出 MD + HTML
python -m pipeline

# 仅生成 HTML（如需指定格式）
python -c "from pipeline import DataPipeline; from datetime import datetime; p=DataPipeline(); p.load_from_files(); p.process(); p.generate_briefing(format='html')"
```

## 4. 产物在哪里看

运行完成后检查以下路径（相对项目根目录）：

| 产物 | 路径 | 说明 |
|---|---|---|
| 主产物 | `output/latest.json` | 汇总去重后的合并结果（sources + stats + items） |
| 附件归集 | `output/latest_attachments/` | 公告 PDF 扁平拷贝 |
| 简报 (MD) | `output/briefings/{YYYY}/{MM}/briefing_{YYYYMMDD}.md` | 当日资讯日报，Markdown 直接预览 |
| 简报 (HTML) | `output/briefings/{YYYY}/{MM}/briefing_{YYYYMMDD}.html` | 当日资讯日报，HTML 内联 CSS，适合邮件/网页渲染 |
| 运行报告 | `output/reports/run_{YYYYMMDD_HHMMSS}.json` | 每源详细状态 + 汇总统计 |
| 调度器日志 | `output/logs/scheduler/{YYYY-MM-DD}.log` | 全链路日志 |
| 原始采集数据 | `output/data/{source}/{YYYY}/{MM}/{DD}/{source}_latest/` | 各源最新批次目录 |

## 5. 推荐验证流程

```powershell
# 方式一：模拟数据（不联网，秒级出结果，校验链路完整性）
python scripts/check_summarizer.py        # 模块 D：汇总 + 附件归集
python scripts/check_briefing_report.py   # 模块 E：简报 + 运行报告

# 方式二：真实数据单源端到端
python -m scheduler.main --sources cninfo

# 方式三：全量真实运行
python -m scheduler.main
```

## 6. 常见现象说明

- **`after_time=0`（汇总后 0 条）**：采集器超采（如拉到 7 天前公告），汇总层按 `TIME_FILTER.default_hours = 24` 统一过滤。这是设计行为——采集器负责超采，汇总层兜底保时效。想临时看更多内容，可把 `config/settings.py` 的 `default_hours` 调大（如 168）。
- **控制台中文乱码/报编码错**：PowerShell 默认 GBK，部分采集器输出 UTF-8 表情符。用 `python -X utf8 -m scheduler.main` 运行即可。
- **单源失败不影响整体**：源状态分为 `ok / failed / warning / timeout`，单源超时（默认 300 秒）会被 kill，其他源继续。
- **源开关**：`config/settings.py` 的 `COLLECTORS` 中 `enabled` 控制启用；`wind`（需授权）、`wechat`（待实现）默认关闭。
- **AI 摘要未生效**：检查 `.env` 是否配置；未配置时采集器自动跳过摘要，其余链路不受影响。

## 7. 常见问题排查

| 现象 | 排查步骤 |
|---|---|
| 启动即报模块缺失 | `python -m scheduler.main --list-sources` 会列出缺失的 `collectors/{code}/crawler.py` |
| 某源一直 failed | 单独跑 `python -m collectors.{code}.crawler` 看原始报错；再开 `-v` 看调度器 DEBUG 日志 |
| 简报缺失 | 检查是否误加 `--no-briefing`；确认 `output/briefings/` 目录有当天 `.md` 或 `.html` 文件 |
| 只需 HTML 简报 | 默认双产出，如需仅 HTML 可用 `python -m pipeline` 配合代码指定 `format='html'` |
| 需要重跑汇总 | `python -m scheduler.main --skip-collect`（不重新采集） |
